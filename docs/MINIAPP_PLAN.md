# Мини-приложение Telegram — план по блокам

Работа идёт в ветке `miniapp`. В `main` (рабочий бот) ничего не меняется до финальной выкладки:
задачи можно продолжать добавлять в `main`, а ветку периодически обновлять (`git merge main`).
Выкладываем только готовый результат — блок 8.

Каждый блок — одна рабочая сессия. В конце блока: тесты зелёные, коммит в `miniapp`,
в этом файле ставим ✅ и пишем, что сделано/что осталось.
Чтобы продолжить в новой сессии: «продолжаем мини-приложение, блок N».

## Архитектура (решено)

- **Тот же VPS**, тот же процесс: веб-сервер aiohttp запускается внутри `bot.py` рядом с polling.
  Вопросы грузятся в память один раз; база `stats.db` общая с ботом.
- Перед ним **nginx** (HTTPS, Let's Encrypt) на домене пользователя. Нужен домен с A-записью на `72.56.30.194`.
- **Авторизация**: каждый запрос несёт `initData` от Telegram, сервер проверяет подпись (HMAC-SHA256 с токеном бота).
  Никаких логинов/паролей.
- **Статистика общая**: ответ в приложении = ответ в боте (та же таблица `answers`, серия дней, «работа над ошибками»).
- **Фронт без сборки**: один `index.html` + `app.js` + `style.css`, скрипт Telegram WebApp, цвета из темы Telegram.
- Правильный ответ **не уходит на клиент** до ответа: проверка на сервере.

## Блоки

### Бэкенд

- [ ] **0. Подготовка.** Вынести из `bot.py` работу с БД и общую логику (init_db, touch_user, record_answer,
  update_streak, get_stats, get_section_stats, get_mistakes, section_title …) в модуль `storage.py`.
  `bot.py` импортирует оттуда — поведение бота не меняется. `tools/test_bot.py` зелёный.
- [ ] **1. Каркас API.** Пакет `miniapp/`: `auth.py` (проверка initData, тесты на правильную/подделанную подпись,
  просроченный auth_date), `server.py` (aiohttp app, middleware авторизации, `GET /api/me`).
  Запуск веб-сервера из `bot.py` по флагу `WEBAPP_PORT` (без флага — всё как сейчас).
- [ ] **2. API контента.** `GET /api/tracks` (треки → группы → разделы со счётчиками),
  `GET /api/section/{track}/{section}` (список id вопросов, порядок перемешан на сервере),
  `GET /api/question/{qid}` (текст, варианты, картинки — без correct/explanation),
  раздача `images/` статикой.
- [ ] **3. API ответов.** `POST /api/answer {qid, choice}` → правильно/нет, правильный вариант, пояснение,
  solution / solution_image(s); пишет в `answers` + серия дней. `GET /api/stats`, `GET /api/mistakes`
  (как «работа над ошибками» в боте), лимиты как в боте.
- [ ] **4. Тест API.** `tools/test_api.py` по образцу `test_bot.py`: прогон всех разделов и всех вопросов через API,
  проверка авторизации, ответов, статистики, ошибок; HTML в тексте безопасен для вывода.

### Интерфейс

- [ ] **5. Каркас фронта.** `miniapp/static/`: экраны «ЕГЭ/ОГЭ/…» → номера → старт; навигация «назад» через
  BackButton Telegram; тема (светлая/тёмная) из Telegram.
- [ ] **6. Экран задачи.** Условие + картинка, варианты (длинные — целиком, без обрезки), ответ, разбор,
  раскрывающееся «Полное решение» с рисунками, переход к следующей, прогресс по тесту, итог.
- [ ] **7. Статистика и ошибки.** Экран статистики (по номерам), серия дней, «работа над ошибками».
  Проверка на маленьком экране.

### Выкладка

- [ ] **8. Запуск.** Домен → nginx + certbot, `WEBAPP_PORT` в systemd, кнопка меню бота «Открыть тренажёр»
  (`setChatMenuButton`) и кнопка в /start. Бэкап `stats.db`, merge `miniapp` → `main`, деплой, проверка на телефоне.
